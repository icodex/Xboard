## 修复：镜像缺 intl 会让上游新代码必崩

- 上游 `User::normalizeEmail()` 无条件用 `\Normalizer::normalize()` 与 `idn_to_ascii()`；而 `phpswoole/swoole:php8.2-alpine` 基线不含 intl，`Dockerfile` 也没装。实测官方镜像 `php -r 'var_dump(class_exists("Normalizer"));'` → `bool(false)`。
- 影响面：每次设置/查询邮箱都会走该路径（登录、注册、后台改用户、迁移），重建镜像后直接 fatal。
- 修复：`Dockerfile` runtime 阶段 `install-php-extensions intl`，并把 `mbstring`/`intl` 加入启动期扩展断言；CI `tests.yml` 扩展清单补 `intl`（此前 CI 未装 intl，测试依赖宿主机恰好有）。
- 验证：`docker build --target runtime` 通过；容器内 `extension_loaded("intl")=true`，实际跑通 `User::normalizeEmail("  Foo@BÜCHER.example ")` → `foo@xn--bcher-kva.example`。
