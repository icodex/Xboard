## 节点侧复测发现 -> 面板修复与矩阵同步

节点侧跑出三类问题，面板对应更新（本次一并提交）：

- **shadowsocks + 显式 xray 的 cipher 收窄**：xray fork `infra/conf/shadowsocks.go` 只解析 aes-128-gcm/aes-256-gcm/chacha20-ietf-poly1305/xchacha20-ietf-poly1305/2022-blake3-aes-{128,256}-gcm，其它值解析成 UNKNOWN 后内核起不来。`ServerSave` 增加 `SHADOWSOCKS_CIPHERS_XRAY`，仅当 `kernel_type=xray` 时覆盖 cipher 规则，并给该场景专属报错文案（避开通配 `protocol_settings.*.in` 覆盖消息的坑）。
- **hysteria1 obfs 受 `obfs.open` 控制**：`ServerService::buildNodeConfig` 与 `app/Protocols/SingBox.php` 的 v1 分支都改为 `obfs.open ? obfs.password : null`，与 v2 语义对齐；否则只填 password 的存量行会“看似配置混淆、实际明文”。
- **订阅补 `http` 传输**：`SingBox.php` 的传输映射新增 `http`（type=http + path/host），此前 vmess/vless 的 http 传输在 sing-box 订阅里缺失。

- `seed-nodes.php`：`Hysteria1-obfs` 补 `obfs.open=true`；shadowsocks 固定内核副本仅对 xray 可解析的 cipher 生成 xray 副本（aes-192 只留 singbox），节点总数 233 -> 232。

## 清理误删事故与修复（PRUNE_STALE）

- 现象：重建镜像后首次 `init.sh` 打印 `PRUNED ... ECH-singbox, ECH-xray, Mux-singbox, Mux-xray, Mux-brutal-singbox total=5`，删掉了测试分组里非种子节点。
- 根因：清理条件只按“分组 + 不在当前种子名单”，没有区分节点来源；节点侧/手工为高级参数建的 ECH/Mux 节点被当成残留。配置已随行删除，sqlite 无可靠恢复手段。
- 修复：seed 写入行统一带 `tags=['dev-seed']`；清理条件收窄为“分组 + `tags` 含 `dev-seed` + 不在种子名单”，手工/节点侧节点不再被触碰。`README` 同步说明。
- 复跑验证：`tagged=232`、`PRUNED` 为空、`total=232 / enabled=231`、门禁全 PASS、`online=0`。
- 遗留：ECH/Mux 5 个节点需节点侧重建后复测；本仓无法恢复其原配置。
